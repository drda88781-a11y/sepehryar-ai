## ۲. مشخصات مؤلفه‌های Sepehryar AI Core

### ۱.۲. Master Agent (`app.agent.master_agent`)
* هدایت‌کننده و هماهنگ‌کننده کلان استدلال چندمرحله‌ای (Reasoning Coordinator).
* فهم نیت کاربر، خرد کردن مسئله به زیرتسک‌های تخصصی (Task Decomposition) و مدیریت حافظه مشترک تخته‌سیاه (Blackboard).

### ۲.۲. موتور استنتاج فرضیه‌ای فرادانش (`app.agent.reasoning.deductive_engine`)
* حذف وابستگی صلب به Knowledge Base؛ اگر پاسخی آماده در داکیومنت‌ها نباشد، هرگز پیام «یافت نشد» صادر نمی‌شود.
* فرضیه‌سازی و تحلیل ساختار جداول، کلیدها، فیلدها و کنوانسیون‌های حسابداری برای رسیدن به راه‌حل‌های نوآورانه و مطمئن.

### ۳.۲. ایجنت‌های ۷گانه تخصصی (`app.agent.specialized`)
1. **Database Agent (`database_agent.py`)**: شناخت عمیق جداول، فیلدها، کلیدهای اصلی و خارجی منطقی (`Sh_ozviat`, `personcod`, `SanadM`)، تریگرها و ایندکس‌ها.
2. **SQL Agent (`sql_agent.py`)**: طراحی و بهینه‌سازی T-SQL با هینت `WITH (NOLOCK)` برای گزارش‌ها و ساختار تراکنشی با `TRY...CATCH` و `XACT_STATE()` برای دستورات اصلاحی.
3. **Procedure Agent (`procedure_agent.py`)**: مهندسی پروسیجرهای سازمانی سپهریار بر اساس الگوهای واقعی، کنترل تریگرها، پارامترهای خروجی (`@ResultCode`, `@ResultMessage`) و حفظ تراز اسناد.
4. **Code Agent (`code_agent.py`)**: طراحی معماری کلاینت/سرویس با زبان C# و .NET، کلاس‌های DTO و متدهای فراخوانی پروسیجر با استفاده از الگوی `using` و جلوگیری از نشت کانکشن.
5. **Debug Agent (`debug_agent.py`)**: ریشه‌یابی خطاها در زنجیره کامل `Error -> Stack Trace -> Code -> SQL -> Database -> Data -> Dependencies -> Root Cause`.
6. **Architecture Agent (`architecture_agent.py`)**: جانمایی ماژولار، ماتریس اثر، تحلیل حوزه‌های غیرقابل تغییر (No-Touch Areas) و ارزیابی ریسک.
7. **Critic Agent (`critic_agent.py`)**: ارزیاب و منتقد کیفی؛ هیچ پاسخ فنی بدون تایید Critic نهایی نمی‌شود.

### ۴.۲. رابط‌های برنامه‌نویسی و اتصال سیستم‌ها (`app.api.routes`)
* `POST /api/brain/solve`: اجرای کامل تفکر چند ایجنتی Master Agent همراه با گواهی Critic و مراحل استدلال.
* `GET /api/brain/agents`: دریافت فهرست ایجنت‌های فعال و توانمندی‌های آن‌ها.
* `POST /api/brain/agents/{agent_role}`: ارسال تسک مستقیم به هر یک از ایجنت‌های تخصصی.

## ۳. مؤلفه‌های پایه‌ای و زیرساختی

### ۱.۳. Offline Guard (`app.core.offline_guard`)
* مسدودسازی فعال در سطح سوکت برای جلوگیری از ارسال بسته‌ها به IPهای عمومی اینترنت.

### ۲.۳. Deep Database Scanner (`app.database.scanner`)
* استخراج ایمن متادیتا از کاتالوگ ویوهای سیستمی SQL Server بدون اعمال قفل.

### ۳.۳. Safe SQL Engine (`app.database.safe_sql`)
* لایه امنیتی جهت مسدودسازی دستورات غیرمجاز در کوئری‌های عمومی و ماسک‌سازی فیلدهای حساس.

### ۴.۳. لایه ذخیره‌سازی محلی SQLite (`app.storage.repository`)
* کش ساختار متادیتا و لاگ‌های حسابرسی در حالت WAL.
